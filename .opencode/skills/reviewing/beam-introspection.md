# BEAM Introspection -- Runtime-First Development

The BEAM VM is a live, introspectable runtime. When Tidewave MCP tools are available,
prefer talking to the running application over grepping files. The application knows
its own modules, routes, schemas, processes, and state -- use that knowledge directly.

## 1. Rules

1. **Prefer runtime tools over filesystem searches** -- `get_source_location` is faster and more accurate than `rg` for finding function definitions.
2. **Use `project_eval` / `eval_with_logs` for exploration** -- they run inside the app with all modules loaded; `mix run -e` spawns a separate VM.
3. **Use `get_docs` instead of web searches** -- returns exact docs for the exact dependency version in your project.
4. **Use `execute_sql_query` through Ecto, not raw sqlite3/psql** -- runs through the app's configured Repo with proper connection pooling.
5. **Clear logs before reproducing an issue** -- `Tidewave.clear_logs()` then trigger, then `get_logs`. Fresh logs with no noise.
6. **Use `ast_search` for structural code patterns** -- text search (`rg`) misses renamed variables; AST search matches structure.
7. **Always `dry_run=true` first with `ast_replace`** -- structural replacements can have unintended matches.
8. **Fall back to `read`/`edit`/`write`/`bash` for file mutations and mix commands** -- runtime tools are for exploration and verification, not file editing.

## 2. Decision Table

| Intent / Situation | Use (Runtime) | Avoid (Filesystem) | Why |
|---|---|---|---|
| Find where a function is defined | `get_source_location` (module.function) | `rg "def create_order"` | BEAM bytecode knows exact file:line; grep matches comments and strings too |
| Read documentation for a dep | `get_docs` (module reference) | Web search for HexDocs | Returns docs for your exact version; no version mismatch |
| Run ad-hoc code in the app | `project_eval` or `eval_with_logs` | `bash "mix run -e '...'"` | Runs inside the live app with all modules/state; no cold boot |
| Query the database | `execute_sql_query` | `bash "psql -c 'SELECT ...'"` | Runs through Ecto Repo; uses app config, connection pool, and type casting |
| Discover Ecto schemas | `get_ecto_schemas` | `rg "use Ecto.Schema"` | Lists all schemas with fields and paths; grep misses macros and modules |
| Read application logs | `get_logs` (tail/level/grep) | Reading terminal output | Structured, filterable, no scrollback limit |
| Inspect running processes | `get_top_processes` | Manual `Process.list` sorting | Pre-formatted with memory, message queue, reductions |
| View supervisor tree | `get_sup_tree` | Writing supervisor traversal code | Full tree with strategies, child specs, and PIDs |
| Inspect a specific process | `get_process_info` (include_state) | Writing `Process.info` code | Structured output with state, links, and monitors |
| Find module dependencies | `get_deps_tree` | `rg "alias\|import"` | Uses Mix.Xref -- shows actual compile-time and runtime callers/callees |
| Get type specs for a module | `get_type_specs` | Running `t(Module)` via eval | All types, specs, and callbacks in structured format |
| Search for code patterns | `ast_search` (pattern) | `rg` for code patterns | Matches code structure, not text; handles variable renaming and formatting |
| Detect code duplication | `find_code_clones` | Manual code review | AST-aware clone detection with refactoring suggestions |
| Check code quality | `check_code_quality` | Manual Credo run | Credo + ex_slop combined; catches LLM anti-patterns |
| Validate JS hooks | `validate_js_hooks` | Manual browser testing | Parses bundle, cross-refs templates, validates callbacks; no browser needed |
| Run JavaScript | `eval_js` | `bash "node -e '...'"` | Embedded QuickJS in BEAM; no Node.js installation needed |

## 3. Patterns

### 3.1 Grep for Function Location

**Severity:** WARN

```elixir
# BAD -- text search has false positives and misses dynamically generated functions
# bash: rg "def create_order" lib/

# GOOD -- BEAM knows the exact location from bytecode
# MCP: get_source_location module="MyApp.Orders" function="create_order"
```

**Why:** `rg` matches inside comments, strings, and docs. It misses functions generated by macros. The BEAM stores exact source locations in compiled bytecode.

### 3.2 Cold-Boot Eval

**Severity:** WARN

```elixir
# BAD -- spawns a new BEAM VM; slow, no access to running state
# bash: mix run -e 'MyApp.Orders.list_orders() |> IO.inspect()'

# GOOD -- runs inside the live application
# MCP: project_eval code="MyApp.Orders.list_orders()"
```

**Why:** `mix run -e` boots a fresh VM (5-15 seconds), does not see runtime state (ETS, GenServer state, connections), and may conflict with the running dev server. `project_eval` executes in the existing process with all state available.

### 3.3 Debugging Without Log Isolation

**Severity:** WARN

```elixir
# BAD -- scrolling through mixed logs to find the relevant ones
# Read terminal output, searching for the error...

# GOOD -- isolated log capture
# Step 1: Clear logs
# MCP: project_eval code="Tidewave.clear_logs()"
# Step 2: Trigger the operation
# Step 3: Read fresh logs
# MCP: get_logs level="error" tail=50
```

**Why:** Production and dev logs accumulate rapidly. Clearing before reproducing ensures you see only the logs from your specific operation, with no noise from background processes.

### 3.4 Unsafe AST Replace

**Severity:** BLOCK

```elixir
# BAD -- replacing without preview can break code
# MCP: ast_replace pattern="IO.inspect(expr)" replacement="expr"

# GOOD -- always dry_run first
# MCP: ast_replace pattern="IO.inspect(expr)" replacement="expr" dry_run=true
# Review matches, then run without dry_run
# MCP: ast_replace pattern="IO.inspect(expr)" replacement="expr"
```

**Why:** Structural patterns can match more broadly than expected. `IO.inspect(expr)` might match inside test helpers or debug modules you want to keep. Always preview first.

## 4. Checklist

- [ ] Used runtime tools (`get_source_location`, `get_docs`) before filesystem search
- [ ] Queries ran through `execute_sql_query`, not raw DB CLI
- [ ] Logs were cleared before reproducing the issue
- [ ] `ast_replace` was run with `dry_run=true` first
- [ ] Process inspection used `get_top_processes` / `get_process_info`, not manual code

## Eval Recipes

### Module Discovery

```elixir
# List all exports of a module
exports(MyApp.Orders)

# Find all modules matching a pattern
:code.all_loaded()
|> Enum.filter(fn {mod, _} -> "#{mod}" =~ "MyApp" end)
|> Enum.map(&elem(&1, 0))
|> Enum.sort()

# Check if a module has a specific function
function_exported?(MyApp.Orders, :create_order, 1)
```

### Phoenix Introspection

```elixir
# List all routes
MyAppWeb.Router.__routes__()
|> Enum.map(fn r -> {r.verb, r.path, r.plug, r.plug_opts} end)

# Check Endpoint config
Application.get_env(:my_app, MyAppWeb.Endpoint)

# Count active LiveView sessions
Process.list()
|> Enum.filter(fn pid ->
  case Process.info(pid, :dictionary) do
    {:dictionary, dict} ->
      case Keyword.get(dict, :"$initial_call") do
        {mod, _, _} -> "#{mod}" =~ "LiveView"
        _ -> false
      end
    _ -> false
  end
end)
|> length()
```

### Ecto Introspection

```elixir
# Schema fields and types
MyApp.Orders.Order.__schema__(:fields)
MyApp.Orders.Order.__schema__(:type, :status)

# Associations
MyApp.Orders.Order.__schema__(:associations)
MyApp.Orders.Order.__schema__(:association, :items)

# Test a query
import Ecto.Query
MyApp.Repo.all(from o in MyApp.Orders.Order, where: o.status == :pending, limit: 5)

# Test a changeset
%MyApp.Orders.Order{}
|> MyApp.Orders.Order.changeset(%{title: "test"})
|> Map.get(:errors)
```

### OTP / Runtime

```elixir
# System memory
:erlang.memory()
|> Enum.map(fn {k, v} -> {k, "#{Float.round(v / 1_048_576, 1)} MB"} end)

# Scheduler info
:erlang.system_info(:schedulers_online)
:erlang.system_info(:process_count)

# GenServer state
:sys.get_state(MyApp.SomeWorker)

# ETS tables by memory
:ets.all()
|> Enum.map(&:ets.info/1)
|> Enum.sort_by(& &1[:memory], :desc)
|> Enum.take(10)
```

## Workflow Summary

1. **Explore** -- `get_source_location`, `get_docs`, `get_sup_tree`, `get_type_specs`, `get_module_functions`
2. **Understand** -- `get_deps_tree`, `get_process_info`, `get_top_processes`, `eval_with_logs`
3. **Edit** -- `read`/`edit`/`write` for file changes
4. **Verify** -- `bash "mix compile --warnings-as-errors"`, `get_logs`, `smoke_test`, `validate_js_hooks`
5. **Quality** -- `check_code_quality`, `find_code_clones`, `ast_search`
6. **Test** -- `bash "mix test test/path.exs:42"`
7. **Format** -- `bash "mix format"`
